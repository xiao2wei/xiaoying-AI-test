# 内容正确优先：最终结果的判定规则

2026-10-31，用户明确要求：“把回答错误的才判为失败。把没有依据的，判为正确，但是需要在文档里面说明，类似‘回答正确，完全符合PDF的规定，但是未完全把依据给出’。”

据此，主判定区分**答案内容正确性**与**依据展示完整性**。这里“没有依据”按用户给出的例子解释为：答案实际符合PDF，但原回答没有完整给出支持依据。若整份PDF也无法支持某结论，不能仅凭听起来合理就判为正确，应继续核查或标记无法验证。

## 判定方法

|情况|当前主判定|文档说明|
|---|---|---|
|回答与PDF一致，直接回应实际问题|正确|无需照抄参考答案所有补充解释|
|回答与PDF一致，但引用缺失、不完整或绑定位置不当|正确|标注“回答内容符合PDF规定，但未完整给出或关联支撑依据”|
|资料不够或有未解决冲突，准确说明缺口、提出具体补充要求|正确处理|不等于已给出确定制度结论|
|工具持续故障，按用例要求如实停止|正确处理|业务仍未完成，不虚报成功|
|工具故障后未达到用例要求，未给出答案|未完成|不记回答错误，也不算正确完成|
|回答与PDF矛盾，或把错误条件、数字、适用范围说成事实|回答错误（失败）|列出错误及原文|
|既不能核实也不能证伪|待核查|不能自动计为正确|

报告主指标为**正确处理率**：整组所有轮次都正确回答或合理处理，才计入；分母固定为全部测试组。错误、未完成、待核查都留在分母。空分母记N/A，不记100%。该指标包含合理追问、资料不足和预期安全停止，因此不称作“所有问题答案正确率”。

缺失关键适用条件、导致结论对用户实际问题错误，仍属于内容错误。仅缺与所问结论无关的附加解释，不再因未覆盖某一句参考要点判失败。

## 为什么不直接重跑基础RAG的3组未完成

已核对原Trace：TEST36、TEST37、TEST40均有fault_injected=true，错误消息明确为“显式测试故障注入”，不是DeepSeek、VPN或SSL造成的外部异常。测试题库分别设置第一次search失败、第一次read失败、search持续失败且工具上限为2。每次建立新会话都会重置注入计数，所以原配置重跑仍会触发这些故障。

基础RAG是固定的一次检索/读取流程，没有观察故障后重新规划的循环；Agent在前两组恢复后回答，在第三组达到上限后如实停止。这个差异是故障恢复测试的结果。关闭故障再运行属于另一个正常场景，不能替换原故障测试来提高通过率。

真正的外部网络/API偶发异常可以在恢复后重测，保留失败尝试、重测原因、配置及新结果，不挑选最好的一次；本次这3组不满足该前提，因此未新增模型请求。

## 核对证据和人的参与

本次Codex对原严格未通过的13项逐项核查实际问题、完整答案、相关PDF条文和原工具记录；旧严格通过的记录沿用已有评审。原先用户确认的56轮正式复核及16项校准记录继续保留。本次逐项内容核对由AI完成，不冒充新的人工逐题标签；用户授权的是判定规则调整。

特别是TEST25：PDF第7页第九条支持“取得学位后1个月内到人事处”；第6—7页第六、七条给出审批/协议程序；第8页第十三条明确未经学校批准不办理相关手续。完整PDF支持答案，但原Agent未读取第十三条。本次补查只能记为**评测核对依据**，不能补进模型的原始引用或Trace。

旧M06引用支持率99.04%、M08按当次已读证据计算的无依据事实率0.48%、3个关键缺陷场景标记及原20项门槛保留为诊断结果。它们与“内容能否由完整PDF核实”是不同口径，不能将这些旧指标悄悄改成100%、0%、0个。
