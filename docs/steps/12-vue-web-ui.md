## 实现

Vue3.5.44 + Vite7.3.7，使用单文件组件，没有引入UI组件框架。Python标准库ThreadingHTTPServer提供本机API并托管构建产物；不新增Python依赖。固定使用127.0.0.1，默认端口8000。检索器只加载一次，任务后台执行，页面轮询任务状态；轮询不调用模型。

服务端管理上下文，最多30段会话、每段8轮、60分钟闲置过期；单一问答执行线程。Web每轮12轮决策/10次工具，CLI原整组预算不变。这个入口差异没有改变冻结的模型、提示词、检索、引用校验与正式评测文件。

只允许静态dist资源和指定PDF；不暴露仓库目录。Host、Origin、CSRF检查保护本地写接口。页面用Vue文本插值展示问答和原文，不执行模型返回的HTML；JSON下载去除提供方原始消息和内部推理。

## 发现的问题与修复

1. 新会话创建是异步的，若在创建完成前双击发送，可能创建两个任务。增加同步发送锁，并用浏览器同一事件循环双击验证仅一次POST。
2. Windows将.js注册为text/plain，导致真实Python静态服务下浏览器拒绝执行脚本；Vite预览测试不暴露这个问题。为JS/CSS明确设置MIME，并增加模拟错误系统注册表的HTTP测试。首次页面加载失败时没有任何DeepSeek请求。
3. 本机8765端口被系统拒绝绑定（WinError10013），改用实测可用的8000；错误说明同时覆盖端口占用和系统保留。
4. 首轮实际回答的两个结论引用同一条款，截图脚本按“查看引用1”查到两个按钮。只修复截图定位，复用已完成首轮，再执行第二问；未重复首轮模型请求。
5. 长页截图中固定于底部的输入框会遮挡中段内容。重拍时使用实际更高视口；执行过程采用组件局部截图。重拍仅GET已有会话，POST和新增模型请求均为0，没有改写答案或合成界面。
