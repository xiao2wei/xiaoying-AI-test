# 正式人工复核：怎么做

本轮指标已由用户接受。这里补的是“人实际核对了哪些答案、依据是什么”的记录。已知失败可以保留；完成复核不要求把原始AI分数全部改成通过，也不自动重启模型优化。

## 需要你做的事

1. 从下方材料打开一个案例，先对照问题、实际回答与原文，核对结论、条件、引用和资料缺口；故障题再看工具结果与最终状态。
2. 看AI是否判对。逐项填“同意AI判定”，或指出“哪一轮、哪句话、为什么不同意、哪条原文支持”。确认不通过也算完成复核。
3. 可以分批在对话中反馈，例如“已核对 A01.1—A03.1，同意各项现有AI判定；A04.1不同意，原因……”。这只是格式示例，不代表已确认。混合通过/失败的一批应说“同意各项AI判定”，避免模糊的“全通过”。
4. 我收到实际反馈后记录复核人（可写项目负责人）、确认时间与原话，保留原分。涉及改分时根据你确认的事实项补充修订理由并本地重算，另列复核后结果；这一流程不需要DeepSeek请求。

## 完成标准

- 56轮都有实际人工结论、理由和确认出处；不能由AI代填。
- 对不同意的评分明确修订哪项事实、引用或要点，保留原评分与修改依据。若不能判断，该项仍待复核。
- 保留AI原始指标；如有改分，另报复核后指标；你已作出的指标接受决定继续有效。
- 全部规定项复核并记录完毕后，步骤八的这项材料才完成；不会自动启动GitHub交付。
