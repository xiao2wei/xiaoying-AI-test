# 项目复盘

最难的问题是把“看起来回答得对”变成可查证的结果。资料提取、模型判断和AI裁判都可能出错，因此每一层都保留证据，而不能只展示一段好答案。

PDF里的比较符号、跨页条款和合并单元格会改变待遇条件。实现先处理字符基线、表格行列关系及页码映射，再做逐页清单和关键条款检查。229页处理成功不代表人工逐字检查；保留核查方式与局限。

Agent早期出现动作JSON无效、通用问题被当作个人审批而多余追问、无关补查耗尽预算。修复后开发集12/12；正式评测暴露引用关联及部分参考要点过严的问题。默认12轮、10次工具尝试和完整错误状态，使失败能明确结束。严格格式接口也需要实测，不能把服务的strict字段当成绝对保证。

AI裁判曾误判复合条件和跨句引用。使用16个人工确认标签校准、程序核对评分跨度，再提供正式人工复核清单；即使用户接受结果，也保留原分和失败。TEST21的复合参考要点未因模型表现而更改。用户明确接受剩余差距，不再追加无止境调参。

成本控制需要落在执行流程。相同输入和配置按哈希复用有效评分，失败评分也复用，不挑高分；纯格式修复采用获批的影响审计，策略改变仍完整回归。网络恢复后只补56轮未决评分，没有重生成答案。本轮最终补评分58次请求、278644 tokens；与账户累计账单口径不同。

当前正式题库已经用于返修，属于回归验证。下一步可另建未见题库，改进结论与引用逐项绑定、冲突适用范围和复合条件评分，并增加跨平台安装验证。这些属于已记录的剩余改进，不改写本轮分数，也不宣称覆盖任意新制度。

个人工时由用户确认“未计时”。源代码、调试和文档主要由Codex完成，个人贡献见04-ai-usage.md；不把这些经验写成未经用户确认的个人独立实现经历。

本次评测复盘进一步区分答案内容与依据展示：用户要求只有答错才标失败。核查发现部分答案回应了实际问题，却被非必要的参考解释句扣分；另有正确结论未完整绑定原文。内容口径因此独立呈现，旧评分不删。Agent正确处理率100.00%、基础RAG92.50%、稳定性100.00%来自对原记录的事后重分类，不代表改进了模型，也不免除引用缺口。基础RAG3组工具未完成仍单列，不计为正确完成。
