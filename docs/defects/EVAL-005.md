# EVAL-005：将行为性要求误判为口号要求

发现于首次正式TEST19：回答明确说明资料不含Wi-Fi密码，未给密码，评分器却以未逐字声明“不能编造”判遗漏。原有人工确认的CAL05已支持“说明资料不足且不编造”的行为解释。修复只明确行为性禁止条件的语义，不放宽正向内容/追问要求，不修改正式答案或阈值。保留14个旧校准，新增CAL15正例与CAL16反例请求真实人工确认。

同时对评分输出的格式/定位校验失败增加一次有反馈的评分修正；只重试机械无效的评分，合法的低分不会自动重评到通过；所有请求与校验失败保留。

另发现评分器对制度标题、版本日期等引用定位元数据的支持判定不一致。澄清原有规则：可由对应已读chunk的元数据支持；文号和实质规则仍须原文证据。程序输出自动附上title与article方便核对，来源不可由模型捏造。

## 推理输出预算修复

开发v7的DEV03评分两次finish_reason=length，completion_tokens分别9999、10000且全部为reasoning_tokens，没有可解析评分正文。模型默认high推理，重复同一请求不能保证产出，且浪费预算。依据DeepSeek官方thinking_mode文档改为独立评分reasoning_effort=low，重新用16项已确认标签校准；回答最终核对仍保持既有high配置。输出截断不再原参数自动重试，明确OUTPUT_TOKEN_LIMIT_REACHED。缓存键增加推理强度，不跨配置复用。官方依据：https://api-docs.deepseek.com/guides/thinking_mode/ 。
