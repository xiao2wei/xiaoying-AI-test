# ANSWER-002：通用制度问题被误当作个人资格核定

## 失败证据

正式v3的TEST25、TEST30及稳定性TEST25中，通用制度问法在已给依据后仍输出needs_confirmation，询问身份或协议。至少两组相似题因此不满足5/6门槛，不能继续把格式重试当作全部修复。

## 统一根因与修复

旧最终核对要求充分列出条件，但没有明确“回答通用规则”与“核定具体个人待遇”的差别。新增通用意图规则：制度条件可以直接表述；只有个人结论真正依赖未知条件才追问。约束回答只包含本题及直接适用前提，避免额外制度陈述和重复gaps事实；没有直接依据的排除关系不扩写。没有把任何测试ID或标准答案写进运行时。

严格动作接口同时修复：所有常规动作直接使用严格submit_action函数格式；最终核对仍先用启用思考的真实模型，只有格式失败时用禁用思考的严格格式修正。官方Chat Completion接口不支持thinking+强制tool_choice，旧候选出现HTTP400；本版已据官方定义修正并保留实际请求模式。未把原文或自述工具结果当真实观察。

该变更改变回答策略，因此不使用格式修复的选择性例外。完整12组开发回归v14通过后才冻结并完整真实运行正式40+40+30。v3完整原始问答已保留，发现必败门槛后停止剩余评分以节省费用；未完成评分明确未完成，终止时在途请求费用不从缺失本地日志推定为零。原先已完成真实评分保留用于诊断。

## 真实验证暴露的补充问题

v14将复杂anyOf封装用于全部动作，真实接口仍出现无效arguments；未进入评分，原返回保留，不能把strict宣称为实测格式保证。最终恢复JSON常规路径，格式失败才使用search/read/finish三个简单函数的严格格式重试，并继续本地验证。v15先运行DEV03，模型读取未命中的条款和非必要标题耗尽10次工具预算，故停止其余11组。v16补充通用预算指引：只读实际候选，批量数不超过剩余额度；冲突双方及相关解释条款已核对仍无衔接时具体追问，不穷举无关标题。仍不放宽10次上限。
