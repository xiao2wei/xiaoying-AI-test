# FORMAT-001：模型动作响应出现多余JSON边界或预演工具结果

## 证据与影响

正式v2的TEST20、TEST27出现格式失败。全量本地回放437条合法响应保持原值不变；原12条冗余格式可恢复。开发format-dev-v12又暴露DEV06在JSON后附带自述、预演工具结果并被截断，整组失败，旧结果保留。format-dev-v11因编排10秒超时中止，单独标记基础设施中断，未用作成绩。

## 根因与修复

JSON Object接口并未保证整个content只有一个动作。不能执行模型伪造的tool_observations，也不能从不同动作中挑选。解析器仅接受一个完整对象、额外右括号、完全相同对象重复；其他尾随内容拒绝。

当动作格式仍失败，保留原有最多2次请求预算及相同错误反馈消息；第二次请求改用DeepSeek beta严格function schema，仅接收submit_action中唯一decision。它只约束传输格式，search/read仍由既有本地工具执行，资料/检索/业务提示/模型/最终核对策略均不变。原生成内容、失败、修复类型、真实response_id及usage全部记录。首次动作被截断时也使用一次不同格式的修正请求；评分器截断仍直接停止，不重复长推理。

官方接口依据：https://api-docs.deepseek.com/guides/tool_calls/ （2026-10-31核对）。严格模式要求beta、strict=true、必填properties与additionalProperties=false。没有将格式合法当成语义正确，原引用和AI评分仍继续。

## 影响范围与复验

按用户批准的格式修复回归方案，审计所有模型响应。额外括号/重复对象/原无效动作/截断动作所在整组全部重跑，包括原本成功的组。稳定性受影响场景3次全部重跑。未受影响原记录逐字复制，记录SHA与原耗时；不是全量新模型结果。基准与Agent均经过审计。当前57项程序测试通过；开发format-dev-v13进行中，未达门槛不得启动新正式回归。
